# Releasing

One version tag, `vX.Y.Z`, releases every client in this repository. Only stable
`X.Y.Z` versions are released. Before tagging, set the versions in `cli/Cargo.toml`,
`sdk/python/pyproject.toml` and `sdk/typescript/package.json` to `X.Y.Z`;
`node scripts/check-release-version.mjs vX.Y.Z` must pass. Never move a published
tag or replace its artifacts.

## What the tag does

Pushing the tag runs `.github/workflows/release.yml`, generated by cargo-dist from
`dist-workspace.toml`:

1. The plan job calls `check-version.yml`, which checks the tag against all three
   versions. Nothing is built unless it passes.
2. cargo-dist builds the CLI archives, the shell and PowerShell installers and the
   CLI npm installer package for every target.
3. The host job creates the GitHub release with those assets.
4. `publish-packages.yml` checks the version again, then publishes `@aadi-labs/sikaru-sdk`
   and the `@aadi-labs/sikaru-cli` npm installer, with provenance, through OIDC trusted
   publishing.
5. When the Release workflow completes successfully, `publish-pypi.yml` checks the
   version again and publishes `sikaru_sdk` to PyPI through OIDC trusted
   publishing.

No registry token is stored in the repository.

The shell installer, `curl -fsSL https://app.sikaru.ai/install.sh | sh`, redirects to the
latest release's `sikaru-cli-installer.sh` and installs into `~/.sikaru/bin` (added to
`PATH`). On Windows:
`powershell -c "irm https://github.com/aadi-labs/sikaru-clients/releases/latest/download/sikaru-cli-installer.ps1 | iex"`.

Do not edit `release.yml` by hand. Change `dist-workspace.toml` and run
`dist generate`; CI fails if the two disagree.

## One-time trusted-publisher setup

Register a trusted publisher for each package, with no environment:

- npm, `@aadi-labs/sikaru-sdk` and `@aadi-labs/sikaru-cli`: repository `aadi-labs/sikaru-clients`,
  workflow `release.yml`. npm checks the workflow that started the run, and
  `publish-packages.yml` is called from `release.yml`. An npm package must exist
  before a trusted publisher can be added to it, so publish a `0.0.0` placeholder
  of each by hand once, then add the publisher.
- PyPI, `sikaru_sdk`: repository `aadi-labs/sikaru-clients`, workflow
  `publish-pypi.yml`. A new project can use a pending publisher; no placeholder.

## Before tagging

Verify a clean installation of the CLI on macOS and Linux:

```sh
cargo install --locked --debug --path cli --root /tmp/sikaru-installed
SIKARU_TEST_INSTALLED=/tmp/sikaru-installed/bin/sikaru cargo test --locked --manifest-path cli/Cargo.toml --test compute_packaged_acceptance
node scripts/check-cli.mjs /tmp/sikaru-installed/bin/sikaru
```

Run the compute lifecycle contracts for all three clients (see
`shared/compute-contracts/README.md`) and the authoring companion checks in
`shared/authoring/README.md`. The `Verify` workflow runs all of these on every push.

## Local cargo-dist runs

Running `dist plan` or `dist generate` locally reorders `cli/Cargo.lock`. The
contents are equivalent, but the file no longer matches generator output.
Regenerating the clients restores it.
